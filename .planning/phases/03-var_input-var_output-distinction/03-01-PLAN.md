Per plc4j (RESEARCH.md), the 8-byte member-record header is:
- bytes 0-1: dataType (uint16)
- bytes 2-3: offset (uint16) — what Dart currently calls "block"
- bytes 4-5: unknown5 (uint16) — candidate direction byte
- bytes 6-7: unknown4 (uint16) — candidate secondary direction byte

Phase 3 reads bytes 4-5 and 6-7 as separate uint16 LE values and passes them to the classifier. We do NOT change how Dart currently builds the parsed `offset` (it reads the 4 bytes as a uint32). The two views coexist — direction is a side-channel attached to the record.

### Task 2 — Create the enum + classifier (TDD green)

File: `packages/tfc_dart/lib/core/umas_fb_direction.dart` (new)

```dart
/// Direction classification for a function-block member.
///
/// Derived from the per-member DD02 record header bytes 4-5 (`unknown5`)
/// and 6-7 (`unknown4`) — fields plc4j parses as opaque uint16 values
/// and does not decode (see UmasUDTDefinition mspec at
/// protocols/umas/src/main/resources/protocols/umas/umas.mspec:214-220).
///
/// Phase 3 maps observed `unknown5` values to a small enum so the Phase 4
/// UI can render input/output/public/in_out distinctly. The mapping is
/// inferred from empirical observation; the classifier returns `unknown`
/// for any combination not in the table so wrong classifications surface
/// as undecorated UI rather than as silent miscategorisation.
enum UmasFbMemberDirection {
  /// VAR_INPUT — operator-facing input to the FB.
  input,
  /// VAR_OUTPUT — FB output exposed to the program.
  output,
  /// VAR — public member, neither input nor output (FB-local public state).
  publicVar,
  /// VAR_IN_OUT — pointer-backed bi-directional member. Direct reads
  /// return 0x94; Phase 5 stretch may add pointer dereferencing.
  inOut,
  /// Bytes do not match any known encoding. Phase 4 renders these without
  /// direction decoration.
  unknown,
}

/// Classify an FB-member direction from the two uint16 LE fields that
/// follow `(dataType, offset)` in the per-member DD02 record header.
///
/// Returns [UmasFbMemberDirection.unknown] for any combination not in the
/// inferred table. Never throws.
UmasFbMemberDirection classifyFbMemberDirection(int unknown5, int unknown4) {
  switch (unknown5) {
    case 0x0001:
      return UmasFbMemberDirection.input;
    case 0x0002:
      return UmasFbMemberDirection.output;
    case 0x0003:
      return UmasFbMemberDirection.inOut;
    case 0x0000:
      if (unknown4 == 0x0000) return UmasFbMemberDirection.publicVar;
      return UmasFbMemberDirection.unknown;
    default:
      return UmasFbMemberDirection.unknown;
  }
}
```

Two views of bytes 4-7 are intentional and benign:
- `offset` reads them as uint32 (current behavior, preserves Phase 2's parse).
- `unknown5` + `unknown4` re-reads the same bytes as two uint16 LE — direction inference.

This is safe because Dart `ByteData.getUint32(4, little) == (getUint16(4, little) | (getUint16(6, little) << 16))`. The classifier views the two halves separately; the existing offset field is unchanged.

Future<int> _browseCommand(UmasClient umas, {bool showDirection = false}) async {
  final tree = await umas.browse();
  final leafCount = _countLeaves(tree);
  print('${tree.length} root(s), $leafCount leaves\n');
  for (final root in tree) {
    _printTree(root, '', showDirection: showDirection);
  }
  return 0;
}

void _printTree(UmasVariableTreeNode n, String indent,
    {bool showDirection = false}) {
  final type = n.dataType?.name ?? '?';
  final addr = n.variable == null
      ? ''
      : ' [block=0x${n.variable!.blockNo.toRadixString(16)} '
          'off=0x${n.variable!.offset.toRadixString(16)}]';
  final dirSuffix = (showDirection && n.direction != null)
      ? ' dir=${n.direction!.name}'
      : '';
  print('$indent${n.name}  ($type)$addr$dirSuffix');
  for (final c in n.children) {
    _printTree(c, '$indent  ', showDirection: showDirection);
  }
}
