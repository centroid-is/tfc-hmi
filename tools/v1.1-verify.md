# v1.1-verify.sh — milestone acceptance harness

## Purpose

`tools/v1.1-verify.sh` is the v1.1 **UMAS Hardening** milestone gate for tfc-hmi3.
It runs the four Phase 6 acceptance criteria (VERIFY-01, VERIFY-02, VERIFY-03, TEST-03) plus
an Advantys STB no-regression smoke check against the live Schneider M580 at 192.168.112.159
and emits one PASS/FAIL/SKIP line per requirement followed by a single gate line.

If the gate line says `v1.1 GATE: PASSED` and the exit code is `0`, v1.1 is shippable.

## How to run

```sh
# Full live gate (PLC required, takes a couple of minutes)
tools/v1.1-verify.sh

# Self-check without running any commands (no PLC required)
tools/v1.1-verify.sh --dry-run

# Local sanity without the (slow) flutter test step
tools/v1.1-verify.sh --no-flutter

# Per-command stdout / stderr echoed for debugging a failure
tools/v1.1-verify.sh --verbose
```

Environment overrides for non-default lab setups:

```sh
PLC_HOST=192.168.50.10 PLC_PORT=502 PLC_UNIT=255 tools/v1.1-verify.sh
```

## What each check covers

| Requirement | What it asserts | Underlying command |
|-------------|------------------|--------------------|
| **VERIFY-02** | Bug A fix — STRING reads no longer emit "underflow" | `umas_cli read 192.168.112.159 stStatusElevator` |
| **VERIFY-01** | Bug B fix — every FB instance (≥23) has children; `M_Elevator` expands | `umas_cli browse 192.168.112.159` |
| **VERIFY-03** | Baseline 35-scalar pass rate preserved; no scalar / array failures | `umas_cli check 192.168.112.159 --json` |
| **TEST-03** | Dart + Flutter test suites green (incl. `umas_*_test.dart`, `umas_browse*_test.dart`, `advantys_stb_test.dart`) | `cd packages/tfc_dart && dart test` + `flutter test` |
| **STB-SMOKE** | Advantys STB fixture (PR #121) still passes — covered by the flutter test run | (covered above; loud NOTE on output) |

## Failure modes & exit codes

| Exit | Meaning | Operator action |
|------|---------|-----------------|
| `0` | `v1.1 GATE: PASSED` (or dry-run completed) | Ship. |
| `1` | `v1.1 GATE: FAILED (N failures)` | Read the per-requirement `FAIL` lines; each contains a `repro:` snippet to re-run that specific check. |
| `2` | `FATAL` — environmental abort (missing `dart` / `flutter` / `python3`, or PLC unreachable) | Fix environment (install tooling, plug in PLC, double-check `PLC_HOST`) and re-run. NOT a v1.1 code failure. |

### Reading the output

Each requirement check emits exactly one of:

```
PASS VERIFY-02 — stStatusElevator read clean, no 'underflow' in output
FAIL VERIFY-01 — only 0/23 FB instances have children (target ≥23) | repro: (cd /repo && dart run packages/tfc_dart/tool/umas_cli.dart browse 192.168.112.159)
SKIP TEST-03  — flutter test skipped via --no-flutter (partial coverage; orchestrator MUST NOT use this for the milestone gate)
```

`SKIP` is permitted but the harness will note it in the totals. The orchestrator MUST NOT count `SKIP TEST-03` as a milestone pass.

## Extending for future milestones

This script is intentionally single-purpose (v1.1). For v1.2+:

1. Clone to `tools/v1.2-verify.sh`.
2. Replace the per-requirement check functions with the v1.2 acceptance commands.
3. Update the requirement IDs in `record_pass` / `record_fail` calls to match v1.2 REQUIREMENTS.md.
4. If a v1.2 gate needs a different PLC, override via `PLC_HOST=...` or hardcode.
5. Consider extracting shared helpers (`record_pass`, `run_capture`, `preflight`) into `tools/_verify_lib.sh` if the harness count grows past two milestones.

## Notes

- **Live PLC required for real gate runs.** The PLC at `192.168.112.159` is customer hardware. Do not run the live gate against a production-active PLC during operating hours — `check` reads dozens of variables.
- **STB live rig** is intentionally out of v1.1 scope. The fixture under `test/page_creator/assets/advantys_stb_test.dart` (covered by `flutter test`) is the regression bar per `.planning/PROJECT.md`. A live-rig STB smoke is a v2 candidate.
- **Dry-run mode does NOT touch the network.** Safe to run anywhere, anytime, to confirm the harness structure.
